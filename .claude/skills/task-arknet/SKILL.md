# ТЗ теху ArkNet

Инструкция от команды техов (arkdesk.cc), прислана Павлом 12.08.2026. **Следовать
дословно.** Образец готовой таски: https://arkdesk.cc/tickets/showTicket/4384

## Каркас таски

```
Скопіювати лендинг - <URL посилання на ленд, який потрібно скопіювати>

Нове посилання/Назва копії:
Назвати лендинг - <Оффер-Гео-Мітка-LP-Назва-ТипЦіни>
Назвати редірект - <Оффер-Гео-Мітка-RD-ТипІнтерактиву>

Дані офферу:
Ваш домен - <домен>
Назва офферу - <товар>
ID в ПП офферу - <id офферу>
Потік ID офферу в ПП - <id flow>
Ваш API Token в ПП - <API TOKEN>
Країна - <ISO2>

Почистити та оптимізувати ленд від зайвих та потенційно шкідливих скриптів,
Внести наступні правки по необхідності:

Ленд 1 (<повна назва ленду>)
* <правка>
* <правка>

Ленд 2 RD (<повна назва редіректу>)
* <правка>
```

**Первая строка — откуда тех берёт ленд: ссылка ИЛИ архив.** Оба варианта равноправны,
выбирает Павел. Ссылка — `Скопіювати лендинг - <URL>`; архив — `Скопіювати лендинг -
архів у файлах` (сам файл прикладывается к тикету). Не переспрашивать и не уговаривать
на ссылку: что прислал, с тем и работаем.

## Нейминг

    ленд      Оффер-Гео-Мітка-LP-Назва-ТипЦіни
    редірект  Оффер-Гео-Мітка-RD-ТипІнтерактиву

- **Оффер** — товар, под который делается ленд
- **Гео** — ISO2, заглавными
- **Мітка** — персональная метка байера. У Павла — **ZD**
- **LP / RD** — что это: лендинг или редирект
- **Назва** — по ТЕМАТИКЕ ленда, не одно и то же слово всегда:
  `NewsVSL`, `MedNewsVSL`, `MedicalBlog`, `BlogVSL`, `Blog`, `Vijesti` (сербские новости)…
  Смотреть на содержимое проклы и называть по жанру
- **ТипЦіни** — `low` / `free` / `full`. **При full хвост НЕ пишем**, при low/free — пишем
- **ТипІнтерактиву** — `Boxes`, `Chest`, `Form`, `Wheel`, `Aids` и т.п.

Несколько лендов на один оффер — номер приклеивается к названию:
`Wirex-EE-GG-LP-NewsVSL2`, `…3`, `…4`.

Примеры из инструкции:

    Wirex-EE-GG-LP-NewsVSL
    FortuFlex-RO-GG-LP-MedicalBlog-low
    BeautyDerm-IT-KD-LP-BlogVSL-free
    Wirex-FR-GG-RD-Chest

## Правки — что писать в списке

Пишем только то, что реально нужно этому ленду. Типовые:

- заменить цену: `Замінити ціну 78 EUR 39 EUR НА 58 EUR 29 EUR`
- заменить текст/топоним: `Замінити У Лондоні сьогодні сонячно НА У Парижі сьогодні сонячно`
- перевести: `Перекласти ленд з англійської мови на французьку за допомогою АІ`
- выделить слова: `(слова health, food, sales — виділити червоним кольором, жирним шрифтом)`
- фото товара: `Замінити фото товару на prod.png`
- название по тексту: `Замінити по тексту Keto Coffee на Wirex`
- имя врача: `Замінити ім'я доктора Marco Reus на Alexander Lacazette`
- валидация телефона: `Поставити валідацію номера телефона код країни 33, після коду 9-10 цифр`
- форма: `Замінити форму замовлення з інтерактивом на іншу форму без інтерактиву`
- **скрипт доп. событий — по умолчанию НЕ ставим**, только если байер прямо просит

## Правила

- **Текст ТЗ — текстом, не скриншотами.** Теху надо редактировать.
- Фото товара кидается в раздел «файли» тикета и вставляется в описание (три точки →
  «Вставити в опис», или Ctrl/Cmd+V).
- После выполнения тех ставит статус «Перевірка». Байер проверяет и ставит «Готово» с
  оценкой. Ошибка теха — возврат в «Зробити» с комментарием.
- **Объёмные правки, не упомянутые в исходном ТЗ, — это НОВОЕ ТЗ**, а не комментарий.
  Поэтому список правок должен быть полным сразу: добавленные потом форма, хедер, футер
  или перевод считаются отдельной задачей.

## Чего в ТЗ НЕТ

Куда прокла шлёт заявку, `config.php`, подключение формы к ПП — это работа теха, писать
об этом не надо. Строки про трекинг, маску телефона и антидубль тоже не пишем.

## Данные оффера — брать из карточки ПП

`ID в ПП офферу`, `Потік ID`, `API Token` берутся из карточки оффера. Если их в карточке
нет — ставим прочерк `—` и говорим Павлу, чего не хватило. Не выдумывать.
